# 通用方法：筛选硬件加速候选

本指南适用于把软件流程中的一个或多个阶段迁移到 FPGA、GPU 或其他加速器。它不依赖特定算法、设备或开发框架。目标是判断完整任务的成本是否下降，而非只比较加速核的延迟。

## 流程

1. 固定基线、候选版本、输入集合、参数、输出定义和计时边界。先确认两条路径结果可比较。
2. 测量目标阶段耗时、调用次数和总任务耗时。记录插桩会不会改变运行时间。
3. 列出替换后的全部成本：准备与打包、传输、同步、核执行、等待、解包、剩余软件和资源机会成本。重叠时间不能重复相加。
4. 计算理论上限。若目标阶段占总耗时比例为 p，完全消除该阶段时的加速上限为 `1 / (1 - p)`；真实实现还会增加调用和数据移动成本。
5. 评估减少往返、复用已有中间结果、合并小任务的可能性。避免为了一个很小的核增加多次传输。
6. 先验证功能和接口，再做小规模端到端测量；结果有希望时，使用同输入、同边界开展完整配对比较。
7. 检查最终资源、时序、容量和回退路径。记录“采用”“停止当前实现”或“证据不足”，并说明证据范围。

## 决策记录

使用 [候选评估模板](candidate_template.md)，分开填写实测值、估算值和未知项。停止候选也要记录原因，后续只有输入、成本假设或实现发生实质变化时才重新评估。

## 限制

阶段耗时占比变化、输入分布变化、调用次数变化或设备时钟变化时，应重新测量。单个最慢样本不能代表真实工作负载；综合报告或核级延迟不能代替系统测量。差异落在测量噪声范围时，不应反复测试直到获得有利结果。
