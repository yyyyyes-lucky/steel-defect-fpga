# 通用方法：定位多环境复现问题

适用于主机、开发板、构建工具、Notebook 和网页服务共同组成的工程。方法本身不绑定操作系统、工具版本、端口或板卡。

## 定位顺序

1. 记录执行位置：主机终端、板端终端还是 Notebook；使用的解释器、工具版本和工作目录也要记录。
2. 找第一处真实错误和对应日志。构建提示缺少 IP 时，回到 IP 生成/导出阶段核对，不要只重复启动系统构建。
3. 对照目标工具的帮助和版本文档确认命令；不要把旧版本入口、参数或脚本名直接套到新版本。
4. 区分 Python 本体、项目依赖、运行包和硬件产物。多个解释器并存时，确认实际启动器使用的解释器。
5. 把会变化的 Notebook 输出、配置和结果与发布追溯分开。执行 Notebook 可能改变文件元数据；不要把自引用哈希校验当成运行条件。
6. 分清设备 API、板端服务和主机网页。端口 READY 只说明对应服务响应，不能证明整条链路或网页已经启动。
7. 确认实际运行的文件来自哪个目录；源码更新不会自动更新旧压缩包或已解压目录，不能混合覆盖历史部署。
8. 修复后只验证受影响的链路，保留第一处错误、修复假设、成功标志和剩余限制。使用[问题记录模板](issue_template.md)。

## 记录原则

不要靠删除超时、guard 或设备检查来换取“通过”，也不要删除个人结果来清理目录。一次成功运行不证明连续运行、跨版本或跨板卡都正确；报告必须写清验证范围。
