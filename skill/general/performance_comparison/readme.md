# 通用方法：成对比较两个实现

适用于两个实现处理同一组输入并输出可比较结果的情形，例如 CPU/FPGA、两个软件版本或两套设备。只有输入、参数、输出要求和计时边界一致，比较才有意义。

## 比较步骤

1. 先定义比较对象与计时范围。核执行、加速器调用、板端处理和完整应用延迟是不同指标。
2. 固定输入、参数及运行环境，分别记录预热和正式测量；每条记录至少含样本标识、轮次、实现名称、耗时与输出摘要。
3. 尽量相邻配对并交替运行顺序，减少温度、频率和后台负载偏差。若实现切换需要重启或重载设备，应把独立会话作为统计单位。
4. 检查输出正确性和任务完成情况；保留超时、失败和慢样本，不因结果不利而删样本。
5. 同一批样本权重相同时，用基线总耗时除以候选总耗时计算整体加速比。不要用逐样本加速比的算术平均代替整体比值。
6. 报告样本数、总耗时、中位数、尾延迟、逐轮变化和差异范围。置信区间应依据实际独立试验结构计算。

## 离线汇总工具

`compare_pairs.py` 使用 Python 标准库读取 JSON，不连接设备、不运行模型，也不判断数据采集是否正确。合成输入示例在 [example.json](example.json)。在工程根目录运行：

```powershell
py -3 -B .\skill\general\performance_comparison\compare_pairs.py .\skill\general\performance_comparison\example.json --baseline cpu --candidate fpga
```

默认字段为配对键 `round,case`、实现字段 `variant`、耗时字段 `pipeline_ms`；可通过命令行参数调整。若数据包含预热记录，显式指定阶段字段和值。工具遇到缺配对、重复键、非正/非有限耗时或未完成记录时会拒绝计算。它不计算掩膜质量，也不能独立证明加速器确实参与了运行。

## 解释结果时的边界

功能正确、测得较快和统计上稳定是不同结论。样本数量大但来自同一运行会话时，不能把每帧都当作独立试验。计时段若含准备、同步、传输、等待或后处理，应按实际边界命名。
