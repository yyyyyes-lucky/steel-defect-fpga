# PYNQ 通用技能：DMA、缓存与缓冲区生命周期

本技能面向 **PYNQ 软件框架**，用于排查 Python/ARM 端通过 Overlay 控制 PL 硬件时的数据传输、缓存一致性和缓冲区生命周期问题。它不绑定某个应用题目、算法、FPGA 板卡型号或 Overlay。技能复用的是 PYNQ 层的排查方法；底层 IP 协议、驱动能力和缓存行为必须按实际环境确认。

## 适用范围

适用于使用 PYNQ Python API 加载 Overlay、访问 IP、分配 DMA 缓冲区并与 PL 交换数据的工程。可用于图像、信号处理、控制和其他自定义硬件加速任务。

这不是通用 DMA 驱动，也不假定所有 Overlay 都使用 AXI DMA、相同寄存器、相同启动顺序或相同缓存一致性机制。若使用的 PYNQ 版本、DMA 类型、总线、驱动或硬件协议不同，先查对应 API 和硬件文档，再验证流程。

## 开始前收集的信息

使用 [PYNQ 运行信息模板](interface_template.md)记录：

- PYNQ、Python、Linux 镜像和板卡的实际版本/型号；
- Overlay 文件及其 IP、DMA 通道、接口和地址信息；
- DMA 的模式、数据格式、长度、对齐和包结束协议；
- PYNQ buffer 的分配方式、实际类型和底层内存所有者；
- CPU 与 PL 的读写方向，以及缓存同步 API 和调用者；
- transfer、wait、IP done/error 的完成语义；
- 最小复现输入、第一处错误、相关日志和寄存器状态。

没有这些信息时，不推断缓存操作或启动顺序。

## 排查流程

1. **确认实际加载的 Overlay。** 核对 `.bit/.hwh` 或当前 PYNQ 版本所用的 Overlay 元数据、IP 名称、地址和 DMA 通道。不要仅凭 Python 变量名判断实际硬件连接。
2. **写清数据契约。** 记录每个通道的方向、元素类型、shape、字节数、位宽、打包方式、对齐、长度限制及包结束条件。核对发送长度、接收容量和 IP 预期一致。
3. **画出缓冲区所有权。** 标出谁分配内存、何时 CPU 写入、何时 PL 读取/写入、谁等待完成、何时 CPU 读取，以及何时才能复用或释放底层 buffer。NumPy view 不等于拥有其底层内存。
4. **确认缓存同步责任。** 查当前 PYNQ buffer API、DMA driver 和平台说明，确定 CPU 写后由谁同步给设备、设备写后由谁同步给 CPU。只有证据确认存在一致性或 API 已维护时，才调整 flush/invalidate 行为。
5. **按硬件协议安排启动。** 根据 IP 控制协议和流接口的 backpressure/packet 规则，确定接收、IP 和发送的顺序。接收优先准备只是常见设计之一，不是所有 Overlay 的固定规则。
6. **等待完整事务结束。** 明确 DMA 通道、IP 控制状态及可能的中断分别意味着什么。只有所有输出生产者完成、设备到 CPU 的可见性已确认后，才能消费输出或复用缓冲区。
7. **分段测时。** 分别记录输入准备、缓存同步、提交到完成、wait、输出同步/复制、解包及应用剩余工作。若观测区间混有调度或核计算，不把它命名为“纯 DMA 时间”。
8. **保留失败现场并恢复。** 记录超时、长度、状态寄存器、当前缓冲区和 Overlay；不要无限重试、删除 timeout 或直接复用状态不明的 DMA/IP。按当前硬件和 PYNQ 运行环境确定恢复步骤。

## 常见症状

| 症状 | 优先检查 | 不要直接做 |
| --- | --- | --- |
| `wait()` 超时 | DMA 状态、传输长度、包结束、IP backpressure、启动协议 | 无限重试或删超时 |
| 输出像上一笔事务 | CPU/PL 缓存同步、是否等完、buffer 是否被覆盖、请求/响应是否匹配 | 偶尔正确就当修复 |
| 首次正常、后续异常 | buffer 生命周期、残留 IP 状态、重复调用协议、并发使用 | 保留 view 同时覆盖底层内存 |
| 换 PYNQ 版本后行为变化 | API 文档与驱动实现、buffer 一致性语义、Overlay metadata | 假设所有版本行为相同 |
| 单个核快但整条任务变慢 | 传输次数、数据布局转换、CPU 处理、调度及同步开销 | 把总退化全部归因于 DMA |

## 可复用提示词

> 我在 PYNQ 环境中通过 Overlay 使用 PL IP。以下是 PYNQ/镜像版本、Overlay IP/DMA 信息、数据格式、buffer 分配和缓存 API、调用顺序及最小失败日志。请先依照这些证据画出 CPU/PL 数据流和 buffer 所有权，列出每个完成条件与缓存同步责任；把确定事实和待验证假设分开。不要猜固定启动顺序或默认缓存行为，不要通过删除 timeout/guard 规避问题。给出最小验证步骤和异常后恢复条件。

## 完成标准与限制

问题记录应包含实际配置、复现步骤、第一处错误、修复假设、最小测试、结果和剩余限制。一次成功传输不证明连续运行正确；模拟通过不证明板端驱动正确；单块板卡验证不构成跨板卡认证。

此技能提供 PYNQ 工程排查方法，不替代对应 PYNQ 版本的 API 文档、驱动源码、Overlay 接口说明和板卡手册。具体缓存调用、DMA API、IRQ 和复位方法均以目标系统为准。
