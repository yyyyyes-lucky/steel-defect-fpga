# 硬件候选评估（2026-10-23）

## 决策

优先推进连续调度的宽 Gaussian 行核；连通域面积统计保留为下一新增硬件候选。
旧 v9.1 软件和 v9 位流保留。此次不是完整相机、YOLO、显示链路验收，也不调整分类阈值。

## Gaussian：已有 C/RTL 证据，整机位流与板测分开验收

现有 13/201 tap 两级 Gaussian 通过四次行核调用完成，包含转置、DMA 和 PS 尾处理。
v9.1 已有计时中 Gaussian 响应中位数约 445～448 ms，约占 class2 的 45%、class4 的 69%；
这是包含 PS 和传输的响应时间，不能当作纯硬件执行时间。

旧核逐像素启动和排空 tap-group 流水线。本候选把像素/group 调度合并为连续循环，
仍使用 8 个对称系数通道、同一系数表、28 位无符号输入和逐次 Q30 舍入。
并未融合四次 DMA，也没有使用近似 Gaussian 或改变边界规则。

第一版连续调度功能正确，但反馈累加的综合时序估计为 8.007 ns，超过包含 2.7 ns
时钟不确定度后的 7.3 ns 有效预算，因此不作为选中实现。
选中第二版使用 carry-save（和、进位分开保存）累加，反馈中不再传播完整 60 位进位。
正系数之和为 2^30，最大输入小于 2^28，最终整数和小于 2^58；60 位状态不会溢出。

| HLS 指标 | 旧核 | 选中候选 |
|---|---:|---:|
| DSP | 32 | 32 |
| BRAM18 | 33 | 33 |
| LUT | 6652 | 8309 |
| FF | 3180 | 4677 |
| 综合估计周期 | 6.912 ns | 6.912 ns |
| 一行像素计算循环周期（随核尺寸） | 6656～12800 | 523～6667 |
| 完整单行调度周期（随核尺寸） | 7183～13519 | 1050～7386 |

两者报告采用同一器件 xc7z020clg400-1、同一 10 ns 目标。
以上为 HLS 估计；BRAM18 不能直接与 Vivado 的 BRAM36 tile 数相混。

整机布局布线检查已通过（仍待板测）：

| Vivado 整机指标 | v9 | 新实验版本 |
|---|---:|---:|
| LUT | 22185 | 22525 |
| FF | 23086 | 23379 |
| BRAM36 tile | 37.5 | 37.5 |
| DSP | 113 | 113 |
| WNS | 0.679 ns | 0.747 ns |
| WHS | 0.017 ns | 0.014 ns |

所有设计时序约束满足；构建脚本要求 DRC 无 Error/Critical Warning 才导出位流。
新位流保留所有原核，只替换 Gaussian IP 的内部调度和累加实现。

验证：

- 复用独立 uint64 卷积生成的 24 组冻结用例，四种核尺寸交替运行；C 仿真和 Verilog
  RTL 联合仿真均通过，整数输出及流结束标记一致。
- 原测试覆盖非法参数、错误 sideband 和高位数据，出错仍排空规定长度，避免中途遗留传输。
- 扩展 C 仿真 14 项通过：四种核分别运行 1 行和 512 行满幅随机输入，以及早/缺失 TLAST、
  错误 KEEP、错误 STRB、高四位非零、513 行非法参数。512 行扩展项属于 C 仿真，
  不宣称已经做过这些项的 RTL 仿真。
- 旧、新核同一套原始测试的 RTL 总仿真周期分别为 692864、258454；
  包含测试控制开销且混合不同核和行数，不能用此比值宣称整机提速。

为什么暂不做四遍完整二维融合：仅 201 tap 竖向窗口的 200 行×512 列×28 bit
理论数据存储已约 350 KiB；还要计入前级窗口、端口分组、FIFO 及现有核。
32 位完整 512×512 中间帧需要 1 MiB，超过器件全部片上 BRAM 容量。
融合并非不可能，但需要额外的分块/DDR/数据流设计，期限内优先实现已有周期收益证据的方案。

## 连通域：精确统计模型可行，尚非硬件核

新增 ccl/ccl_stats.cpp 是固定容量的主机 C++ 原型：
8 连通、逐行 run-length 扫描、union-by-rank、已结束连通块立即结算、活跃标签每行重新编号。
只返回连通块数量、前景像素数、最大面积，以及面积不少于 8/20 的块数。
不返回标签图、保留区域掩膜、轮廓、方向或几何特征。

在最大 512 列下，每行最多 256 段，上一行活跃块不超过 256；
暂存上一行活跃块与本行新段只需 512 个节点。前景总数/面积用 32 位计数。
测试包括 512×512 的 65536 个独立连通块，避免错误地把总块数限制为 16 位。
这里的 C++ 工作区大小不是综合 BRAM 用量，顺序循环也不是每周期一个像素的证明。

主机验证 ccl/ccl_host_validation.json：

- 172 个构造/随机用例通过，包括空白、满幅、对角连接、大量孤立点、最后一行合并、
  单行/单列、奇数尺寸、100 个随机尺寸，以及额外非法尺寸检查。
- 冻结 184 帧/403 ROI 的运行中捕获 1028 次 OpenCV 连通域调用，834 个不同掩膜；
  C++ 统计与 OpenCV 完全一致。
- 掩膜来自冻结运行时、Q30/Q20 Gaussian 整数参考、Q8 特征参考及 v9.1 描述子算法，
  sigma3 在主机用等价 CPU 算法计算；不是板端捕获或整机性能结果。

| 调用位置 | 全量调用次数 | 当前统计型原型可否完整替代 |
|---|---:|---|
| mask_stats | 258 | 算法结果范围可覆盖；仍待接口/综合/板测 |
| hysteresis | 240 | 否，还需强像素关联和输出筛选掩膜 |
| inclusion_stats | 78 | 否，还需最大块掩膜、稳定并列选择和几何信息 |
| filter_components | 86 | 否，还需输出筛选掩膜 |
| supported_union | 86 | 否，还需支撑关联与合并掩膜 |
| region_properties | 212 | 否，还需轮廓/几何信息 |
| candidate_summary | 68 | 否，还需标签关联等下游信息 |

这些是函数调用数量，不能把旧 profiling 中嵌套函数的时间相加。
旧板测 mask_stats 每次中位数约 4.5 ms，仅作量级参考，不冒充当前 v9.1 微计时。
因此“先做统计核”具备存储可行性，但预计直接可替代范围有限；
扩大到面积筛选、强像素/支撑标记并返回掩膜，才可能覆盖更大热点，需单独设计和验收。

## 板测判据与后续顺序

1. 完成 Gaussian 候选整机综合、布局布线、时序与 DRC，生成独立 bit/hwh；
   只有构建检查通过才封包。
2. 同一 notebook 先做 24 组核用例、12 个系统用例的新旧对照，以及旧—新—新—旧计时。
   双方使用完全相同的 v9.1 PS 路径，记录总链路和 Gaussian 响应时间，观察两个先后顺序。
3. 冒烟正确且出现稳定收益后再做 184 帧/403 ROI + 3 个补充用例的新位流回归。
   pass 只说明正确性/流程通过，不表示性能自动合格，不自动升级正式版本。
4. 通过后再考虑正式版本集成与重复稳定性；旧 v9/v9.1 保留可回退。
5. 连通域继续优先于零碎 PS 微优化，但先明确“统计”与“返回掩膜”的硬件范围，
   取得综合/周期/传输估算后再决定是否新增到下一位流。
6. 相机、YOLO 与显示的完整链路在独立演示阶段验证；本轮聚焦 Gaussian 行核优化。

## 已查阅的公开资料及适用边界

- [AMD Vitis Vision 流水与数据流概览](https://xilinx.github.io/Vitis_Libraries/vision/2022.1/overview.html)：
  支持尽量流式连接算子、减少中间传输的架构方向，不证明本项目 7020 上的实际速度。
- [AMD Vitis Vision API](https://xilinx.github.io/Vitis_Libraries/vision/2022.1/api-reference.html)：
  直方图、均值/标准差、相位、Otsu 有硬件实现，但固定点格式与当前严格 float32 结果并不自动等价；
  其他器件/时钟下的资源和速度不能套用于本板。
- [Real-time single-pass connected components analysis algorithm](https://link.springer.com/article/10.1186/1687-5281-2013-21)：
  支持逐行复用标签与流式特征累积方向，不证明本项目带掩膜输出和 DMA 的端到端收益。
